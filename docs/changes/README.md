# Changes

Merged PR descriptions and generated GitHub release notes are the primary change
record. Keep behavior, compatibility, validation and operator impact in the PR.
Update the relevant specification, schema and operator documentation alongside
the implementation.

- [Unreleased operator notes](unreleased.md): concise summaries only when useful.
- [0.1.0 development history](0.1.0.md): the first release's retained summary.
- [0.1.0 individual notes](releases/0.1.0/): historical numbered records, not work
  items or a sequence to continue.

Individual notes under `unreleased/` are optional. Use a descriptive filename
when a cross-PR explanation or migration procedure warrants a separate note.
At release time, fold useful notes into the versioned summary and clear the
unreleased area. See the [change process](../dev/change-process.md).
