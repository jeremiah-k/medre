# Plugin System

MEDRE gains a declarative plugin type contract beside adapters, sharing the registration machinery while carrying a separate contract. Plugin types register through the `medre.plugins` entry-point group and are discovered into an immutable registry that stores declarative metadata only, never imports implementations, and retains broken, mismatched, conflicting, or reserved-capability providers as discovery failures with healthy providers unaffected. `SymbolRef` and the registration token grammar move to `medre.registration` as the shared primitive for adapter and plugin declarations, with existing adapter import paths unchanged.

The `PluginSpec` declaration separates capability declaration from operator authorization: effective grants are the intersection of declared, granted, and host-supported capabilities, `modify_routes` stays reserved, and stage subscriptions cover the enrich, transform, and event-policy stages with stage-neutral `input_kinds` and `output_kinds` drawn from the closed event-kind registry. Every plugin requesting `emit_events` declares its allowed output kinds, the host rejects undeclared output kinds, and plugins are not invoked for unrelated inputs. Stage decisions are typed — pass, derive, supersede, allow, and deny with a required reason — and a pure host validator checks policy verdicts, superseding replacements, transform kind flows, and stage-specific decision authority. Derived-event proposals carry an independent positive payload schema version instead of copying the source event's version, advancing the closed plugin execution record envelope to v2 as a prerelease contract change with no legacy fallback.

The host owns durable execution state in SQLite: execution records with deterministic attempt and produced-event identities in an additive table that preserves existing schema-version-1 evidence, frozen execution-plan digests bound per source event and scope before invocation, namespaced instance and replay state, and atomic commits of evidence, derived events, and state revisions. Repeated commits acknowledge stored results; stale revisions, conflicting decisions, changed plans, and corrupt evidence fail closed. Failed invocations retain classified sanitized evidence without writing plugin state or inventing successful decisions, and only successful buffered state writes advance a revision. Mutable mapping-proxy defaults were replaced with independent factories so the contract modules import on Python 3.11.

Stage execution runs explicitly assembled enrichment, transformation, and policy stages between store and route, inline and durably, with a forward-only instance cursor, host-wide expansion bounds, and cooperative cancellation limits. Every configured instance is validated before implementations load; instances serialize, derived events continue through all downstream gates, and interrupted acknowledgements reuse committed outcomes. Plugin-configured pipelines reject routing and delivery replay until replay can preserve the qualified frontier, while historical inspection and re-rendering remain available. Settled required failures, incompatible plans, and exhausted retries consume the bounded ingress failure budget, while retry delays, pending cancellation, shutdown, and stale uncommitted state snapshots use operational deferral; the durable claim queue rotates least-recently updated work behind untouched pending rows. Failure evidence keeps truncation markers inside the shared 512-character error-detail limit, reapplying redaction after truncation so sanitized records round-trip through durable storage unchanged.

A first-party reference plugin deriving `plugin.custom` text statistics serves as the conformance fixture. The dormant list-returning protocol, `validate_plugin_payload`, and `PluginBoundaryError` scaffolding symbols are removed under the prerelease contract policy. The normative contract is specified in `docs/spec/plugins.md`.
