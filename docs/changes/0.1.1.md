# MEDRE 0.1.1 release notes

This patch release adds explicit package source switching, selects the merged
adapter fleet revisions, records the SimpleX Chat native replies capability,
documents the Meshtastic startup packet drain and reconnect receive watermark,
adds container distribution and operator image builds, reports the running
installation at startup, and packages the current adapter configuration schema. See the [release and
merged PRs](https://github.com/jeremiah-k/medre/pulls?q=is%3Apr+is%3Amerged)
and the [archived individual notes](releases/0.1.1/).

## Package source switching

`medre sources show` separates configured source catalogs, uv's saved request
and installed provenance. `medre sources switch` selects index releases, Git
revisions or local checkouts for core and installed adapters, with a read-only
dry run. New first-party adapter requests default to index releases; existing
catalogs and installed requests retain their choices, and the legacy
`adapters reset` command continues to select upstream Git main. Switching
preserves extras, markers and unrelated requests: uv retains resolution and
receipt ownership, and supported local editable requests survive replay.
Displayed sources redact URL credentials and query strings; actual execution
arguments are unchanged, and a redacted preview is not a copyable command.
(#520)

## Meshtastic startup drain and reconnect receive watermark

The selected Meshtastic provider drains packets for 15 seconds after its first
receive-ready connection. Set `startup_packet_drain_seconds: 0` to disable the
initial drain and the unknown-age reconnect bootstrap; the initial drain
does not rearm on transparent reconnect. Production
examples enable the setting explicitly, and immediate-ingress test fixtures
disable it so they continue to exercise their intended routing behavior.

After a transparent reconnect, a radio can empty its queue of pre-reconnect
packets. The provider records a receive-ready watermark per connection
generation: the `rxTime` cutoff is judged against the packet's own
generation's watermark, and a fixed five-second, generation-scoped window
drops packets that arrive without a usable `rxTime` right after a reconnect.
Provably fresh traffic relays immediately, subject to ordinary admission, a
rapid reconnect retires any remaining initial drain, and the timestamp cutoff
persists for the generation. No new configuration key: the drain opt-out also
disables the reconnect window, and `startup_backlog_suppress_seconds` remains
the cutoff tolerance. (#509, #510, #512)

## SimpleX Chat native replies

The promoted simplexchat revision records the native replies capability: the
machine-readable declaration and the transport profile state native quote
replies with thread and plain-text fallbacks, and the transport limitations
appendix describes retained-parent quotes with inline fallback text instead of
a pending qualification candidate. (#519)

## Support bundles and configuration schemas

Support bundles report the active configuration schema when the packaged
`current/adapter-config.schema.json` artifact is present. Release packaging
retains both the frozen 0.1.0 baseline and the current adapter configuration
schema; the released top-level snapshots and their freeze digests remain
unchanged. The current schema adds only the optional Meshtastic
`startup_packet_drain_seconds` field, and the older closed baseline schema
rejects that field. (#510)

## Container distribution

Build and qualify an immutable all-adapter image on Linux amd64 before
publishing it to GHCR. The default build uses the committed compatibility
snapshot; custom builds can select index packages, local checkouts or source
catalogs. Make and Compose support read-only, non-root operation with persistent
state. Release and development tags have separate publication authority;
qualification verifies installed revisions and terminal shutdown. See the
[Docker deployment guide](../ops/docker.md) for build inputs, credentials,
hardware access and update procedures. (#523)

## Tooling and qualification

Live-test peer observation moves off the runtime loop, keeping shared radio
fixtures from contending with runtime scheduling. Disposable lab certificates
generate under strict OpenSSL mode compliance. The repository unifies its
quality-check entry points and contributor conventions; dependency automation
moves to the current Renovate configuration. (#506, #507, #513, #514, #516,
#518)

## Startup installation summary

`medre run` reports the core, Python and installed provider versions before
adapters start, with recorded install provenance and redacted source URLs.
The summary reads installed metadata without loading provider implementations;
unreadable metadata affects only the relevant fields or marks the inventory
incomplete, without blocking startup. The labels describe installed metadata,
not source-tree cleanliness or qualified source bytes. (#530)
